# Остатки агентств из Telegram

Балансы рекламных агентств подтягиваются автоматически из ежедневного отчёта,
который сотрудник публикует в рабочем Telegram-чате. Сервис читает чат ботом,
парсит сообщение со списком агентств и обновляет балансы на вкладке
**«Компания» → «Рекламные агентства»**. Ручная правка суммы остаётся —
автосинк её перезапишет при следующем отчёте.

## Как это работает

- Бот состоит в чате и читает сообщения (long-polling `getUpdates`).
- Фоновый воркер каждые ~15 минут дёргает `/api/sync/telegram`.
- Эндпоинт берёт **самое свежее** сообщение-отчёт с момента прошлого синка,
  разбирает строки вида `Название — сумма`, и для каждой строки:
  - находит агентство по названию (без учёта регистра) и обновляет баланс,
    дату «обновлено» и подпись «кто внёс» (имя автора сообщения);
  - если агентства нет — создаёт новое (можно отключить
    `TELEGRAM_AGENCY_AUTOCREATE=false`).
- Позиция в ленте (`offset`) хранится в БД (`TelegramState`), поэтому одни и те
  же сообщения не обрабатываются повторно.

## Формат сообщения

Одно сообщение со списком агентств. Заголовок/дата игнорируются. Примеры строк,
которые корректно распознаются:

```
Остатки агентств 09.06
Meta Ads — 128 400$
Google Ads: 86 200
TikTok Ads 42 750$
Microsoft Ads = 18 300
X / Twitter — 9 100$
```

Поддерживаются разделители `—`, `–`, `-`, `:`, `=`, `·`, `•`, `>`, `|`, таб;
разделители тысяч (пробел, неразрывный пробел, запятая), символы валют
(`$`, `USDT`, `руб`), суффиксы `к`/`k` (тысячи) и `млн`/`m`. Строки-заголовки
(«Остатки…», «Баланс…», «Итого…», даты) отбрасываются.

Сообщение считается отчётом, если содержит слова из `TELEGRAM_REPORT_MARKER`
(по умолчанию `остат|баланс|агентств`) **или** в нём ≥2 распознаваемых строк
вида «название — сумма».

## Настройка бота

У нас есть сервисный бот **@financeanalyticsUnico1_bot**. Проверить и подключить:

1. **Токен.** Открыть @BotFather → `/mybots` → выбрать бота → **API Token**.
   Если бот недоступен/утерян — создать новый: `/newbot`, получить токен.
2. **Приватность.** @BotFather → `/mybots` → бот → **Bot Settings** →
   **Group Privacy** → **Turn off** (Disable). Без этого бот в группе видит
   только команды/упоминания, а не обычный текст отчёта. _Альтернатива:_
   сделать бота администратором чата.
3. **Добавить в чат.** Пригласить бота в рабочий чат, где публикуются остатки.
   Если бот уже был в чате до отключения privacy — удалить и добавить заново
   (настройка применяется при добавлении).
4. **Узнать chat id.** Попросить сотрудника написать в чат любое сообщение,
   затем открыть в браузере (подставив токен):
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — найти
   `"chat":{"id":-100...}`. Для группы id — отрицательное число.

Дальше есть два пути прописать секреты — **без доступа к серверу** (через
GitHub) или вручную по SSH.

### Путь A — без SSH, через GitHub Actions (рекомендуется)

Если вы не заходите на сервер сами, но настроен авто-деплой (секреты `VPS_*` и
`DEPLOY_ENABLED=true`):

1. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New
   repository secret**, добавить два секрета:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — id чата (отрицательное число).
2. Вкладка **Actions → Configure Telegram → Run workflow**. Workflow по SSH
   пропишет оба значения в `.env` на сервере и перезапустит контейнеры.
   Значения секретов в логи не попадают.
3. Готово. Воркер дёрнет `/api/sync/telegram` по расписанию; после первого
   отчёта сотрудника агентства обновятся.

> Запускать **после** того, как код интеграции выкатился на прод (миграция
> создаёт таблицу `TelegramState`).

### Путь B — вручную по SSH

1. Зайти на сервер: `ssh ПОЛЬЗОВАТЕЛЬ@IP_СЕРВЕРА`.
2. Прописать секреты в `.env` (в репозиторий не коммитятся):
   ```bash
   cd ~/capital && nano .env
   ```
   ```
   TELEGRAM_BOT_TOKEN="123456:ABC..."
   TELEGRAM_CHAT_ID="-1001234567890"
   ```
3. Перезапустить: `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d`.

> Важно: на боте **не должен** быть установлен webhook — иначе `getUpdates`
> вернёт ошибку 409. Снять: `curl "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"`.

## Режим webhook (когда с сервера нет доступа к Telegram)

Если сервер **не может обращаться** к `api.telegram.org` (исходящие к Telegram
блокируются дата-центром — симптом: синк отвечает `fetch failed`, проба связи
даёт таймаут), поллинг `getUpdates` работать не будет. Тогда используем webhook:
Telegram сам пушит сообщения на наш сервер.

> ⚠️ Сработает только если **входящие** от Telegram на ваш домен:443 проходят.
> Если фильтрация двусторонняя — нужен прокси или смена региона VPS.

Шаги:

1. **Секрет.** Придумайте длинную случайную строку (например, `openssl rand -hex 32`).
2. **Пропишите секрет на сервере.** Без SSH: GitHub → Settings → Secrets →
   добавьте `TELEGRAM_WEBHOOK_SECRET`, затем Actions → **Configure Telegram → Run**
   (workflow допишет его в `.env` и перезапустит контейнеры). Или вручную в `.env`.
3. **Зарегистрируйте webhook из браузера** (с сети, где Telegram доступен —
   `setWebhook` это исходящий запрос, с самого VPS он не пройдёт). Откройте,
   подставив токен, домен и секрет:
   ```
   https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<ВАШ_ДОМЕН>/api/telegram/webhook&secret_token=<СЕКРЕТ>&allowed_updates=["message","channel_post","edited_message","edited_channel_post"]
   ```
   Ответ `{"ok":true,...}` = webhook принят.
4. **Проверка.** `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo` — покажет
   `url`, `pending_update_count` и `last_error_message`. Если Telegram не может
   достучаться до сервера — здесь будет ошибка (значит входящие тоже режутся).
5. После этого сотрудник публикует отчёт → Telegram пушит на
   `/api/telegram/webhook` → агентства обновляются. Эндпоинт защищён секретом
   (заголовок `X-Telegram-Bot-Api-Secret-Token`).

Снять webhook (вернуться к поллингу): убрать `TELEGRAM_WEBHOOK_SECRET` и открыть
`https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather (обязательно) | — |
| `TELEGRAM_CHAT_ID` | Ограничить обработку одним чатом (рекомендуется) | все чаты |
| `TELEGRAM_REPORT_MARKER` | Regex-маркер сообщения-отчёта | `остат\|баланс\|агентств` |
| `TELEGRAM_AGENCY_AUTOCREATE` | Создавать неизвестные агентства | `true` |
| `TELEGRAM_REPORT_SENDER` | Доверенные авторы отчёта (через запятую): имя из «внёс …», `@username`, username или id. Когда задан — чужие сообщения в чате игнорируются | все отправители |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет webhook; включает режим webhook (поллинг off) | — |
| `SYNC_TELEGRAM_CRON` | Расписание воркера (поллинг) | `*/15 * * * *` |

## Диагностика

- Ручной workflow **Actions → Verify server config** покажет, заданы ли
  `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`, и последние строки логов воркера
  (там видно ответ `/api/sync/telegram`).
- Ответ синка содержит `consumed` (сколько апдейтов прочитано), `updated`,
  `created`, `skipped` и `entries` — удобно для отладки парсинга.
